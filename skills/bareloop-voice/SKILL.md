# Bareloop voice

Bareloop publishes about AI systems and automation for marketing, content and
operations teams. The register is a practitioner writing to other practitioners
who are busy and have been sold to before.

Every other skill in this project inherits from this file. Load it first.

## Rules

1. **Evidence before claim.** A sentence asserting a benefit sits next to the
   thing that proves it: a number, a file, a screenshot. If the proof does not
   exist, cut the sentence. Do not soften it into a vaguer version of itself —
   a hedged unproven claim is still an unproven claim, just harder to check.

2. **One idea per sentence.** Narration is synthesized. Stacked subordinate
   clauses fall apart when read aloud by a model.

3. **Name the cost.** Every system has one: maintenance, a failure mode, a case
   where it is the wrong tool. Copy that omits the cost reads as a pitch.

4. **Failures are the product, not a confession.** Write them in the same flat
   register as everything else. No apology, no drama, no lesson-learned arc.
   What broke, why, what the fix was.

5. **No fabricated history.** Do not write "last month I…", "after three months
   of…", or any experience claim that has not happened. This is a young
   publication; invented tenure is the fastest way to lose the one thing it has.

6. **Never frame anything as income.** No "make money with", no earnings, no
   ROI promises. It crosses into financial advice, which YouTube penalises and
   which this publication is not qualified to give.

## Words we do not use

unlock · supercharge · game-changer · leverage (as a verb) · seamless ·
effortless · revolutionary · 10x · hack · secret · insane · crazy · literally ·
deep dive · dive in · in today's fast-paced world · the future of · must-have ·
AI-powered (as a bare adjective) · empower · elevate · robust · cutting-edge

## Before and after

The rules above are approximate. These pairs are the specification.

**Hype → specific**
- ✗ This workflow will 10x your content output.
- ✓ This workflow turns one long asset into six platform cuts. The drafting still takes as long as it did.

**Vague benefit → measured**
- ✗ Save hours every week with automation.
- ✓ The report used to take one person a morning. Now it runs on a schedule, and nobody opens it unless it breaks.

**Hedging → commitment**
- ✗ It might be worth considering whether a skill could potentially help here.
- ✓ Use a skill here. If the task runs less than once a month, don't.

**Feature list → consequence**
- ✗ Claude Skills support markdown instructions, on-demand loading and project scoping.
- ✓ A skill loads only when the work calls for it. So you can keep instructions you would never paste into every prompt.

**Borrowed authority → mechanism**
- ✗ In my experience, retrieval is always better than fine-tuning.
- ✓ Retrieval changes what the model can see. Fine-tuning changes how it writes. Most "the model doesn't know our product" problems are the first kind.

**Passive dodge → owner**
- ✗ Some issues were identified with the output.
- ✓ The digest invented two product launches.

**Invented tenure → present tense**
- ✗ After months of running this, I've learned that skills drift.
- ✓ A skill is a file. Files go stale, and nothing tells you when.

## Format

- Sentences short. Paragraphs two to four sentences.
- Numerals for numbers, including under ten. They scan faster.
- No emoji in scripts or titles. Sparingly in social, never more than one.
- Em dashes over parentheses for asides.
- Lowercase for tool names as their makers write them: `n8n`, not `N8N`.
